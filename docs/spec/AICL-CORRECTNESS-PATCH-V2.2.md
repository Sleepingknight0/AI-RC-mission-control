## 1. Executive decision

Patch นี้แก้ข้อผิดพลาดเชิง correctness หกจุดและทำให้ delivery order ตรงกับความเสี่ยงจริง:

| Area | Previous behavior | Version 2.2 decision |
|---|---|---|
| Connector event deduplication | `UNIQUE NULLS NOT DISTINCT` ครอบ source columns ทั้งหมด | ใช้ origin constraint + partial unique index เฉพาะ connector-originated events |
| Revision | session revision เพิ่มตามทุก durable event/checkpoint | `last_event_seq` เพิ่มทุก durable event; resource revision เพิ่มเฉพาะ mutation ของ resource นั้น |
| Approval concurrency | approval ผูกกับ global session revision | approval ใช้ compare-and-set บน approval row, runtime generation, turn state และ expiry |
| Runtime recovery | Connector restart อาจ `reattach` provider process | Codex/Claude baseline ไม่รองรับ process reattach; restart หมายถึง runtime lost และ resume ใน process ใหม่ |
| Turn queue | `queued` เป็น optional dormant state | baseline ไม่มี server-side queue; active turn อยู่แล้วให้ reject ตรง ๆ |
| Payload limits | WebSocket 1 MiB แต่ inline diff 5 MiB | inline diff จำกัด 512 KiB; payload ใหญ่ใช้ artifact endpoint |
| Database rationale | จำนวน Connector ถูกใช้เป็นเหตุผลเลือก PostgreSQL | จำนวน Connector ไม่ใช่ DB-engine criterion; SQLite เป็น default, PostgreSQL เป็น scale-up profile |
| Delivery order | foundation มาก่อน provider evidence | Codex protocol spike เป็น Phase 0A ก่อน schema/default tuning |

หลักเดิมที่ยังคงไว้:

- `Session / Runtime / Turn / Connection` แยกกัน
- normalized provider-independent protocol
- durable command records และ `commandId` idempotency
- append-before-broadcast สำหรับ durable events
- ephemeral stream frames ไม่ใช่ source of truth
- `outcome_unknown` เป็น first-class state
- ห้าม auto-resubmit ambiguous prompt หรือ side effect
- runtime `generation` ผูกกับ approval และ provider request
- database constraints บังคับ invariant

# 2. Critical fix: connector event source uniqueness

## 2.1 Failure in the previous schema

รูปแบบเดิม:

```sql
UNIQUE NULLS NOT DISTINCT (source_connector_id, source_event_id)
```

ทำให้ `(NULL, NULL)` ถือว่าเท่ากัน จึงเก็บ Core-generated event ที่ไม่มี connector source ได้เพียงหนึ่งแถว เช่น:

```text
session.created
command.accepted
approval.expired
turn.completed
system.incident.created
```

event ตัวที่สองจะชน unique constraint ทันที

## 2.2 Normative event-origin model

เพิ่ม origin ที่ชัดเจน:

```text
core       generated by AICL Core
connector  received from a specific Connector journal
```

กฎ:

- `origin = core` → `source_connector_id` และ `source_event_id` ต้องเป็น `NULL`
- `origin = connector` → source ทั้งสองค่าต้องไม่เป็น `NULL`
- dedupe connector event ด้วยคู่ `(source_connector_id, source_event_id)`
- Core event dedupe ด้วย `event_id` หรือ command/domain key ของ event นั้น ไม่ใช้ source pair

## 2.3 Corrected SQLite schema

```sql
CREATE TABLE session_events (
  event_id                 TEXT PRIMARY KEY,
  session_id               TEXT NOT NULL REFERENCES sessions(id),
  seq                      INTEGER NOT NULL,
  schema_version           INTEGER NOT NULL,
  origin                   TEXT NOT NULL CHECK (origin IN ('core', 'connector')),
  runtime_id               TEXT REFERENCES runtimes(id),
  runtime_generation       INTEGER,
  turn_id                  TEXT REFERENCES turns(id),
  source_connector_id      TEXT REFERENCES connectors(id),
  source_event_id          TEXT,
  event_type               TEXT NOT NULL,
  payload_json             TEXT NOT NULL CHECK (json_valid(payload_json)),
  created_at               TEXT NOT NULL,

  UNIQUE (session_id, seq),

  CHECK (
    (origin = 'core'
      AND source_connector_id IS NULL
      AND source_event_id IS NULL)
    OR
    (origin = 'connector'
      AND source_connector_id IS NOT NULL
      AND source_event_id IS NOT NULL)
  )
) STRICT;

CREATE UNIQUE INDEX uq_session_events_connector_source
ON session_events (source_connector_id, source_event_id)
WHERE origin = 'connector'
  AND source_connector_id IS NOT NULL
  AND source_event_id IS NOT NULL;
```

## 2.4 Corrected PostgreSQL scale-up schema


ห้ามใช้ `UNIQUE NULLS NOT DISTINCT` กับ nullable source pair นี้

## 2.5 Required tests

1. insert Core event `(NULL, NULL)` อย่างน้อย 100 แถวได้
2. connector A ส่ง source event `e-1` ซ้ำ → แถวที่สองถูก reject/deduplicated

5. `origin=core` แต่มี source field → check constraint fail

# 3. Critical fix: separate event sequence from resource revision

## 3.1 The previous coupling is invalid

`last_event_seq` และ `revision` มีหน้าที่คนละอย่าง:

- `last_event_seq` ใช้ replay durable event ตามลำดับ
- revision ใช้ optimistic concurrency บน resource ที่ผู้ใช้กำลัง mutate

ห้ามเพิ่ม global session revision ตาม:

- stream checkpoint
- message batch
- command output batch
- usage checkpoint
- incident/log event ที่ไม่เปลี่ยน resource ซึ่ง command กำลังแก้

มิฉะนั้น approval ที่ผู้ใช้กำลังกดจะ stale เพราะ event ที่ไม่เกี่ยวข้อง

## 3.2 Normative counters

### Session row

```text
last_event_seq       increments once for every durable session event
state_revision       increments only when Session projection/config changes
```

### Runtime row

```text
revision             increments only when Runtime row changes state/config
```

### Turn row

```text
revision             increments only when Turn row changes state/input metadata
```

### Approval row

```text
revision             increments only when Approval row changes
```

หนึ่ง state mutation อาจ emit durable events มากกว่าหนึ่ง event:

- resource revision เพิ่มหนึ่งครั้งต่อ successful mutation
- `last_event_seq` เพิ่มหนึ่งครั้งต่อ durable event

## 3.3 Corrected session schema

```sql
CREATE TABLE sessions (
  id                    TEXT PRIMARY KEY,
  provider              TEXT NOT NULL,
  provider_session_id   TEXT,
  project_id            TEXT NOT NULL REFERENCES projects(id),
  cwd                   TEXT NOT NULL,
  account_profile_id    TEXT NOT NULL REFERENCES provider_profiles(id),
  model_id              TEXT,
  title                 TEXT NOT NULL,
  status                TEXT NOT NULL,
  state_revision        INTEGER NOT NULL DEFAULT 0 CHECK (state_revision >= 0),
  last_event_seq        INTEGER NOT NULL DEFAULT 0 CHECK (last_event_seq >= 0),
  created_at            TEXT NOT NULL,
  updated_at            TEXT NOT NULL,
  archived_at           TEXT
) STRICT;
```

## 3.4 Durable sequence allocation

Pure durable event ซึ่งไม่เปลี่ยน Session projection:

```sql
UPDATE sessions
SET last_event_seq = last_event_seq + 1,
    updated_at = :now
WHERE id = :session_id
RETURNING last_event_seq;
```

Session projection mutation:

```sql
UPDATE sessions
SET status = :next_status,
    state_revision = state_revision + 1,
    updated_at = :now
WHERE id = :session_id
  AND state_revision = :expected_state_revision
RETURNING state_revision;
```

จากนั้น allocate durable event seq และ insert event ใน transaction เดียวกัน

ห้ามมีคำสั่งทั่วไปว่า `revision = revision + 1` ใน event append helper

## 3.5 Resource-scoped preconditions

แทนที่ global `expectedRevision` ด้วย precondition ที่ระบุ resource:

```ts
interface ResourcePrecondition {
  resourceType: "session" | "runtime" | "turn" | "approval";
  resourceId: string;
  expectedRevision: number;
}

interface ClientCommand<T = unknown> {
  commandId: string;
  connectionId: string;
  sessionId: string | null;
  precondition?: ResourcePrecondition;
  type: CommandType;
  payload: T;
}
```

ตัวอย่าง:

- rename session → session `stateRevision`
- change session config → session `stateRevision`
- interrupt turn → turn `revision` + runtime generation
- resolve approval → approval `revision`; **ไม่ใช้ session revision**

## 3.6 Approval row and compare-and-set

```sql
CREATE TABLE approval_requests (
  id                       TEXT PRIMARY KEY,
  session_id               TEXT NOT NULL REFERENCES sessions(id),
  runtime_id               TEXT NOT NULL REFERENCES runtimes(id),
  runtime_generation       INTEGER NOT NULL,
  turn_id                  TEXT NOT NULL REFERENCES turns(id),
  provider_request_id      TEXT NOT NULL,
  action_type              TEXT NOT NULL,
  state                    TEXT NOT NULL,
  revision                 INTEGER NOT NULL DEFAULT 0 CHECK (revision >= 0),
  payload_json             TEXT NOT NULL CHECK (json_valid(payload_json)),
  expires_at               TEXT NOT NULL,
  resolved_by_device_id    TEXT,
  resolved_at              TEXT,
  created_at               TEXT NOT NULL,
  updated_at               TEXT NOT NULL,
  UNIQUE (runtime_id, provider_request_id)
) STRICT;
```

Approval resolution ต้องเป็น compare-and-set ที่แถว approval เอง:

```sql
UPDATE approval_requests
SET state = :resolved_state,
    revision = revision + 1,
    resolved_by_device_id = :device_id,
    resolved_at = :now,
    updated_at = :now
WHERE id = :approval_id
  AND state = 'pending'
  AND revision = :expected_approval_revision
  AND runtime_id = :runtime_id
  AND runtime_generation = :runtime_generation
  AND turn_id = :turn_id
  AND provider_request_id = :provider_request_id
  AND expires_at > :now
  AND EXISTS (
    SELECT 1
    FROM runtimes r
    WHERE r.id = approval_requests.runtime_id
      AND r.generation = approval_requests.runtime_generation
      AND r.state IN ('starting', 'healthy', 'degraded')
  )
  AND EXISTS (
    SELECT 1
    FROM turns t
    WHERE t.id = approval_requests.turn_id
      AND t.state = 'awaiting_approval'
  )
RETURNING id, state, revision;
```

Affected row ต้องเท่ากับหนึ่ง หากเป็นศูนย์ให้ fetch authoritative row แล้ว map เป็น error ที่ชัดเจน:

```text
APPROVAL_ALREADY_RESOLVED
APPROVAL_EXPIRED
APPROVAL_RUNTIME_CHANGED
APPROVAL_TURN_NOT_ACTIVE
STALE_APPROVAL_REVISION
```

ห้าม map ทุกกรณีเป็น `STALE_CLIENT_STATE`

## 3.7 Required tests

1. stream checkpoint 1,000 event ไม่ทำให้ approval revision เปลี่ยน
2. approval pending revision 0 ยังคง approve ได้ระหว่างข้อความ stream
3. device สองเครื่อง approve พร้อมกัน → สำเร็จหนึ่งคำสั่งเท่านั้น

5. approval หมดอายุใน transaction ก่อน update → reject
6. session title เปลี่ยนระหว่าง approval → approval ยัง resolve ได้ถ้า approval row ยัง valid

# 4. High fix: remove provider-process reattach from baseline

## 4.1 Supported recovery distinction

ต้องแยกสี่กรณี:

| Failure | Provider process | Supported action |
|---|---|---|
| Browser disconnect | ยังอยู่ใน Connector เดิม | replay browser cursor; runtime ไม่เปลี่ยน |
| Core channel/Core restart | Connector เดิมยังถือ process/stdio/SDK client | Connector reconnect + journal replay; runtime generation เดิม |
| Connector process restart/crash | stdio pipe หรือ in-process SDK client สูญหาย | runtime lost; spawn process ใหม่; provider session resume |
| Windows restart | process ทั้งหมดจบ | runtime lost; spawn process ใหม่; provider session resume |

คำว่า `reattach` ห้ามใช้กับ Codex App Server over stdio หรือ Claude Agent SDK client ใน baseline

## 4.2 Runtime generation rule

แก้จาก:

```text
ทุกครั้งที่ spawn หรือ reattach ให้เพิ่ม generation
```

เป็น:

```text
ทุกครั้งที่ spawn provider runtime process/client ใหม่ ให้เพิ่ม generation
Core/transport reconnect ที่ Connector process เดิมยังถือ provider runtime ไม่เพิ่ม generation
```

## 4.3 Adapter capability

```ts
interface ProviderCapabilities {
  supportsSessionResume: boolean;
  supportsProcessReattach: boolean;
  supportsConcurrentTurns: boolean;
  supportsInterrupt: boolean;
  supportsApprovals: boolean;
}
```

ค่า baseline:

```text
Codex stdio adapter:
  supportsSessionResume = true when generated schema/runtime proves it
  supportsProcessReattach = false

Claude Agent SDK adapter:
  supportsSessionResume = true when SDK/session mode proves it
  supportsProcessReattach = false
```

UI และ reconciler ห้ามแสดง action ที่ capability ไม่รองรับ

## 4.4 Connector restart algorithm

เมื่อ boot ID ของ Connector เปลี่ยน:

1. mark runtime generation เก่า `lost`
2. invalidate pending approvals ของ generation เก่า
3. active Turn → `outcome_unknown` เว้นแต่ provider history มี terminal evidence ที่ตรวจสอบได้
4. ห้าม resolve promise/approval เดิม
5. ห้าม auto-resubmit prompt
6. ตรวจ orphan process เฉพาะ process ที่พิสูจน์ว่า AICL เป็นผู้ launch ด้วย PID + start time + executable + launch marker
7. terminate/quarantine orphan ที่พิสูจน์ได้; ห้าม attach เข้า stdio เดิม
8. เมื่อผู้ใช้เลือก Resume ให้ spawn provider process/client ใหม่
9. เพิ่ม runtime generation
10. resume ด้วย provider session/thread ID + `cwd` + account profile เดิม

`runtime.resume` หมายถึง **new runtime process + provider session resume** ไม่ใช่ PID reattach

## 4.5 Connector reconnect payload

Connector process เดิม reconnect Core ส่ง:

```text
connector identity
boot ID
journal high-water mark
owned live runtimes
runtime generation
provider session IDs
PID + process start time
provider versions
pending approval IDs
```

Core ตอบได้เฉพาะ:

```text
continue_owned_runtime
resume_journal_replay
invalidate_approval
stop_verified_orphan
mark_outcome_unknown
spawn_new_runtime_and_resume_session
```

ลบ decision `reattach`

## 4.6 Required tests

1. restart Core โดยไม่ restart Connector → runtime generation เดิมและ turn stream ต่อได้
2. restart Connector กลาง turn → old runtime lost, turn `outcome_unknown`
3. old PID ยังอยู่แต่ stdio owner หาย → ไม่ attempt reattach
4. resume หลัง Connector restart → new runtime ID/generation และ provider session ID เดิม
5. approval จาก old generation → reject เสมอ

# 5. Payload-limit correction

## 5.1 Normative limits

ทุก limit วัดจาก **decoded, uncompressed UTF-8 payload** ไม่ใช่ขนาดหลัง WebSocket compression

```yaml
protocol:
  maxWebSocketMessageBytes: 1048576       # 1 MiB
  maxInlineEnvelopeBytes: 786432          # 768 KiB, leaves envelope/headroom
  maxPromptBytes: 262144                  # 256 KiB
  maxOutputBatchBytes: 262144             # 256 KiB
  maxInlineDiffBytes: 524288              # 512 KiB
  maxArtifactMetadataBytes: 65536         # 64 KiB
```

`Single normalized event` ต้องไม่เกิน `maxInlineEnvelopeBytes` เมื่อ serialize แล้ว

## 5.2 Diff delivery

```text
Diff <= 512 KiB serialized
  → inline durable event allowed

Diff > 512 KiB
  → store as artifact
  → WebSocket sends metadata/reference only
  → client fetches through authenticated HTTP endpoint
```

artifact metadata:

```ts
interface ArtifactReference {
  artifactId: string;
  mediaType: string;
  byteLength: number;
  sha256: string;
  downloadPath: string;
  expiresAt?: string;
}
```

HTTP endpoint ควรรองรับ:

- authentication/app session
- Range requests สำหรับไฟล์ใหญ่
- immutable content hash
- maximum transfer policy
- no filesystem path disclosure

ห้าม chunk diff 5 MiB เป็นหลาย WebSocket messages แล้วให้ client เดาว่าเป็น atomic artifact เว้นแต่มี explicit chunk protocol, checksum และ completion record ซึ่งไม่อยู่ใน baseline

## 5.3 Required tests

1. 512 KiB diff ผ่าน inline path
2. 512 KiB + 1 byte ใช้ artifact path
3. message เกิน 1 MiB ถูก reject ก่อน allocation ใหญ่
4. compressed payload ที่แตกแล้วเกิน limit ถูก reject
5. artifact hash mismatch ทำให้ diff viewer ปฏิเสธข้อมูล


- เก็บฝั่ง client หรือ draft store แยก
- ไม่ใช่ Turn
- ไม่มี `turn_id`
- ไม่ถูก auto-send หลัง reconnect
- ผู้ใช้กดส่งใหม่เมื่อ active Turn จบ

## 6.2 Corrected turn states

```text
committed
dispatching
accepted
streaming
awaiting_approval
interrupting
interrupted
completed
failed
outcome_unknown
```

ลบ:

```text
queued
cancelled  # หากมีไว้เฉพาะ queued turn
```

## 6.3 Corrected active-turn index

SQLite:

```sql
CREATE UNIQUE INDEX uq_turn_one_executing_per_session

WHERE state IN (
  'committed',
  'dispatching',
  'accepted',
  'streaming',
```

## 6.4 Protocol and UX

- queue action surface

# 7. Database deployment decision and rationale

## 7.1 Default profile

```text
AICL Core authoritative database: SQLite WAL
AICL Connector durable journal: separate SQLite WAL file
```

เหตุผล:

- one operator
- one Core writer process
- local NTFS
- no direct Connector access to Core database
- simpler install/update/backup/restore
- one SQL/runtime family across Core and Connector

จำนวน Connector ไม่ใช่เหตุผลเปลี่ยน database engine เพราะ Connector คุยกับ Core ผ่าน protocol และห้าม mutate Core DB โดยตรง

## 7.2 PostgreSQL scale-up criteria

PostgreSQL มีเหตุผลเมื่อเกิดอย่างน้อยหนึ่งข้อ:

- มี Core writer มากกว่าหนึ่ง instance
- database แยกเครื่องจาก Core
- ต้องการ HA/failover หรือ PITR จริง
- กลายเป็น multi-user/multi-tenant
- analytics/retention/write load ทำให้ SQLite writer/checkpoint เป็น bottleneck จาก benchmark
- fault domain ของ local disk ไม่ยอมรับได้
- ต้องใช้ PostgreSQL-specific operational tooling ที่มี runbook และ restore drill แล้ว

ลบเหตุผล:

```text
พร้อมรองรับหลาย Connector
```

เพราะ Connector count ไม่เปลี่ยนจำนวน database writers ใน architecture นี้

## 7.3 SQLite does not remove application concurrency controls

แม้ SQLite serialize writer แต่ยังต้องมี:

- single Core database-writer actor
- bounded mutation queue
- `BEGIN IMMEDIATE`
- expected state/resource revision predicate
- affected-row verification
- unique/check/foreign-key constraints
- no retry after ambiguous provider dispatch

single-writer ไม่ได้ทำให้ stale command หรือ logical race หายเอง

# 8. Clarify append-before-broadcast

แทนที่ §5.2 ด้วยข้อความนี้:

> Durable event ต้อง commit ก่อน broadcast เพราะ browser ห้ามเห็น authoritative state ที่ database ยังไม่มี ส่วน ephemeral stream frame เช่น token delta และ stdout delta ใช้ validate-before-broadcast, coalesce และ checkpoint ตาม §20.3; `message.completed` หรือ terminal item record เป็น authoritative source of truth

Pipeline:

```text
Provider message
    ↓
Validate + normalize + classify
    ├─ Durable event
    │    ↓ transaction commit
    │    ↓ broadcast
    │
    └─ Ephemeral frame
         ↓ size/order/generation validation
         ↓ coalesce 20–50 ms
         ↓ broadcast
         ↓ periodic durable checkpoint
```

`last_event_seq` ใช้เฉพาะ durable events/checkpoints ไม่ใช้ต่อ raw token delta

`state_revision` ไม่เพิ่มจาก checkpoint เว้นแต่ checkpoint transaction เปลี่ยน resource projection อื่นจริง

# 14. Additional schema hardening used by the consolidated 2.2 specification

The consolidated specification additionally requires the runtime ID/generation pair to be a real database relationship:

```sql
-- in runtimes
UNIQUE (id, generation)
```

```sql
-- in session_events
CHECK (
  (runtime_id IS NULL AND runtime_generation IS NULL)
  OR
  (runtime_id IS NOT NULL AND runtime_generation IS NOT NULL)
),
FOREIGN KEY (runtime_id, runtime_generation)
  REFERENCES runtimes(id, generation)
```

```sql
-- in approval_requests
FOREIGN KEY (runtime_id, runtime_generation)
  REFERENCES runtimes(id, generation)
```

Connector source IDs must be generated before journal insertion as UUIDv7/ULID values and never reused across Connector boots. A local integer journal offset is not a valid `source_event_id`.

This prevents:

- an approval from referring to a real runtime ID but the wrong generation
- a durable event from carrying a mismatched runtime/generation pair
- source-event collisions after Connector restart or journal recreation

# 15. Validation performed

The corrected SQLite DDL was executed against SQLite 3.46.1 with foreign keys enabled. The contract test verified:

- 100 Core-origin events with `(source_connector_id, source_event_id) = (NULL, NULL)` inserted successfully
- duplicate Connector source event for the same Connector was rejected
- the same source event ID from a different Connector was accepted
- malformed origin/source combinations were rejected
- runtime-generation mismatch was rejected by the composite foreign key
- a second executing Turn was rejected
- the removed `queued` state was rejected by the Turn-state check
- 50 event-sequence updates did not change approval revision
- approval compare-and-set succeeded once and the second resolution attempt failed

This validates the schema contract only. It does not replace the required Codex spike on the target Windows machine.
