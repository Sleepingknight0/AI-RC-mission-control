## Identity, timeline, and capabilities

`RemoteSessionRef` contains provider ID, account ID, optional provider Session
ID, and optional AICL Session ID. A bound case is one logical conversation.
URL/session-storage restoration retains all present identities; account or
provider changes fence stale identities.

Timeline items preserve `source = aicl | provider_native`. Stable provider Turn
correlation can suppress only the native operator item represented by an AICL
accepted prompt; text equality never deduplicates. Provider-native identities
never masquerade as AICL Turn IDs.

Each Session independently projects evidence for discovery, history, live
observation, resume, submit, steer, interrupt, approval, model, reasoning,
execution mode, attachment, diff, and terminal output. Every value carries
support, freshness, source, and a bounded false reason. `canControl=false` does
not suppress safe history/observation, and inventory never promotes authority.

### Binding lifecycle and safe retry

Normalized binding state now distinguishes `unbound`, `binding`, `ready`,
`failed`, `stale`, `external`, and `unsupported`. Catalog and Session capability
snapshots carry binding revision, bounded failure evidence, and retry authority.
Mobile derives its header, banner, empty state, composer, and retry action from
that same evidence; account readiness is labeled separately from Session
binding readiness.

Connector emits structured, bounded preparation errors for project,
authentication, provider, and provider-model failures. A Retry is accepted only
when all of these remain exact and current:

- AICL-created Session with no provider Session ID and no Turn;
- explicitly safe pre-provider failure code;
- provider and account;
- binding revision;
- Connector Runtime ID and generation;
- current enabled/authenticated create-Session capability.

Retry changes the same durable binding row under compare-and-set, dispatches
one idempotent `connector.session.create`, contains no prompt, and never falls
back to another account. Wrong-account, stale-revision, stale-generation, and
duplicate-command tests fail closed. A prior-generation ready binding projects
as stale rather than controllable.
