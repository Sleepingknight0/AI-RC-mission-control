# M6.2 Security and Boundary Self-Audit

Date: 2026-08-02

Reviewed range: `baedde2..db2191e`, plus the complete working tree

Scope: WebSocket/HTTP trust, identity, schema and payload boundaries, project
root containment, Windows path behavior, artifact authorization and allocation,
provider process spawning, secrets, error disclosure, browser rendering, and
approval replay. Correctness remediation remains deferred to M7.1.

## Verdict

The M6.2 audit is complete, but the final Prototype 0 gate must remain closed.
The independent review lenses reported 6 Standards findings and 6 Spec findings.
Their overlap is retained deliberately rather than merged or reranked: the
Standards axis contains 2 Critical, 2 High, and 2 Medium findings; the Spec axis
contains 4 High and 2 Medium findings. Together they represent eight distinct
remediation themes. No source remediation was implemented in this milestone.

## Standards

### ST-01 — Unauthenticated cross-site browser control

- **Severity:** Critical
- **Affected:** `apps/core/src/server.ts:696-725,762-771`
  (`attachBrowser`, HTTP upgrade) and
  `packages/protocol/src/index.ts:253-261` (`approval.resolve`).
- **Reproduction:** Open `/ws` with `Origin: https://evil.example`, receive
  `server.hello`, then submit a Turn after a Connector is present.
- **Evidence:** The in-memory probe received the process-wide artifact bearer,
  obtained `command.accepted`, and exercised the normal mutation path. Upgrade
  selection checks only URL path; `deviceId` is self-asserted by the client.
- **Violated standard:** AGENTS requires explicit protocol/authorization
  boundaries and authenticated artifacts; the specification requires trusted
  Origin checks. Loopback alone does not prevent a malicious web page from
  opening a WebSocket to localhost.
- **Remediation:** Enforce an exact configured Origin allowlist before upgrade,
  require a per-launch or authenticated browser capability, and derive actor or
  device identity server-side. Do not issue artifact authority before auth.
- **Regression test:** Reject absent/untrusted Origin and unauthenticated list,
  subscribe, submit, interrupt, approval, and artifact-token requests while the
  configured application Origin continues to work.

### ST-02 — Connector impersonation and replacement

- **Severity:** Critical
- **Affected:** `apps/core/src/server.ts:518-541,740-771`
  (`handleConnector`, `attachConnector`, upgrade handling).
- **Reproduction:** Connect to `/connector` from an untrusted Origin and send a
  self-asserted `connector.hello`, then submit a prompt from a browser socket.
- **Evidence:** The probe installed `attacker-runtime`; Core accepted the browser
  mutation and the forged Connector received `INTERCEPTED_SECRET_PROMPT`.
  `attachConnector` also closes an existing Connector before authenticating the
  replacement.
- **Violated standard:** Core and Connector are separate trust boundaries;
  Connector identity must not be self-asserted or share browser authority.
- **Remediation:** Use a distinct Connector credential/challenge bound to its
  identity, authenticate before replacement or message handling, and never send
  that credential to browser clients.
- **Regression test:** Reject unsigned/incorrect Connector hello, forged durable
  events, replayed credentials, and unauthorized attempts to evict a legitimate
  Connector.

### ST-03 — Missing canonical project-root containment

- **Severity:** High
- **Affected:** `apps/connector/src/main.ts:13-27` (`projectPath`) and
  `apps/connector/src/codex/adapter.ts:200-217,312-330` (provider start/resume
  and approval handling).
- **Reproduction:** Set `AICL_PROJECT_PATH` to an outside directory, UNC path,
  or an allowed-looking directory whose child is a Windows junction outside the
  intended repository, then start Connector.
- **Evidence:** The value is passed directly as provider `cwd`. There is no root
  registry, `realpath`/canonical comparison, denylist, ACL check, or reparse-point
  policy, and the repository has no path-boundary test.
- **Violated standard:** AGENTS mandates project-root allowlists and canonical
  path checks; Prototype 0 includes exactly one root selected from an allowlist.
- **Remediation:** Resolve and register canonical roots, fail closed on relative,
  UNC, device, denied-system, and outside-root paths, and validate Windows
  symlink/junction containment before runtime creation and sensitive actions.
- **Regression test:** Cover `..`, case aliases, trailing-dot/space forms, UNC and
  device paths, file symlinks, directory symlinks, and Windows junction escape.

### ST-04 — Artifact channel has no aggregate quota

- **Severity:** High
- **Affected:** `apps/connector/src/client.ts:107-172`
  (`emitFileChange`), `packages/protocol/src/index.ts:100-106,526-542`,
  `apps/core/src/store.ts:1076-1239`, and
  `apps/core/src/server.ts:125-150`.
- **Reproduction:** Declare an artifact with huge `byteLength`/`chunkCount`,
  stream chunks, or request a byte range from a large completed artifact.
- **Evidence:** The schema accepted `Number.MAX_SAFE_INTEGER` for both aggregate
  fields. A nominal 128 KiB chunk accepted 196,608 decoded bytes. Core retains
  all chunks and uses `Buffer.concat`; range retrieval loads the full SQLite blob
  before slicing.
- **Violated standard:** AD-013 and the M6.2 prompt require internally consistent
  hard ceilings before large allocation and bounded artifact retrieval.
- **Remediation:** Add a measured `MAX_ARTIFACT_BYTES`, exact chunk-size/count
  relation, per-Turn/backlog quotas and stale-ingest cleanup. Stream hash/storage
  and range reads rather than concatenating/loading the whole artifact.
- **Regression test:** Reject oversized declarations, decoded chunks, cumulative
  bytes, inconsistent counts, quota exhaustion, and prove small ranges do not
  allocate the complete blob.

### ST-05 — Provider inherits the complete service environment

- **Severity:** Medium
- **Affected:** `apps/connector/src/codex/rpc-process.ts:149-159`
  (`CodexRpcProcess.start`).
- **Reproduction:** Put an unrelated secret in Connector's environment, start
  the provider, and inspect the provider or a prompt-triggered child process
  environment.
- **Evidence:** Spawn uses `{ ...process.env, NO_COLOR, LOG_FORMAT }`; no allowlist
  or secret classification exists. The provider can therefore read credentials
  unrelated to Codex or the selected project.
- **Violated standard:** AGENTS forbids logging secrets and the security design
  requires an allowlisted provider environment with credentials remaining in
  the provider/OS store.
- **Remediation:** Construct a minimal cross-platform child environment from an
  explicit allowlist, document required Codex variables, and use credential
  references rather than copying unrelated application secrets.
- **Regression test:** Seed canary secrets and assert they are absent from the
  spawned environment, protocol frames, database projections, and logs while
  required PATH/home/Codex authentication still works.

### ST-06 — Artifact media type is not safely constrained

- **Severity:** Medium
- **Affected:** `packages/protocol/src/index.ts:100-106`
  (`ArtifactReferenceSchema`) and `apps/core/src/server.ts:141-150`.
- **Reproduction:** Validate/store an artifact with `mediaType = text/html` or a
  value containing CR/LF, then request it with valid artifact authority.
- **Evidence:** Both active HTML and `text/plain\r\nX-Probe: injected` passed the
  protocol schema. Core copies the value into `Content-Type` and sends neither
  `X-Content-Type-Options: nosniff` nor attachment disposition.
- **Violated standard:** External values must be validated before an HTTP header
  boundary; artifact retrieval must not turn provider metadata into active or
  invalid response headers.
- **Remediation:** Use an allowlist of inert artifact media types, reject control
  characters, add `nosniff`, and default unknown content to attachment-safe
  `application/octet-stream`.
- **Regression test:** Reject CR/LF and active media types and assert safe headers
  for known, unknown, GET, HEAD, and range responses.

## Spec

### SP-01 — Browser and Connector WebSockets lack required trust gates

- **Severity:** High
- **Affected:** `apps/core/src/server.ts:696-771`, especially immediate token
  issuance at lines 698-701 and unauthenticated upgrade at lines 762-771.
- **Reproduction:** Use `Origin: https://evil.example` for both endpoints, install
  a forged Runtime, and submit a prompt.
- **Evidence:** Browser and Connector were both accepted, the bearer token was
  disclosed, mutation committed, and the forged Connector received the prompt.
- **Violated requirement:** M6.2 requires WebSocket Origin/auth assumptions;
  specification §§16.4-16.5 require Connector identity, Origin validation, and
  authenticated connections.
- **Remediation:** Separate browser and Connector authentication, exact-Origin
  validation, challenge/credential replay protection, and authorization before
  any snapshot, token, replacement, or mutation.
- **Regression test:** Cross-origin browser, replayed browser capability, forged
  Connector, credential replay, and unauthorized replacement must all fail.

### SP-02 — Artifact admission and range retrieval are unbounded

- **Severity:** High
- **Affected:** `packages/protocol/src/index.ts:100-106,526-542`,
  `apps/core/src/store.ts:1076-1259`, and `apps/core/src/server.ts:125-150`.
- **Reproduction:** Announce an enormous artifact/chunk count or issue a tiny
  range request for a large stored blob.
- **Evidence:** Huge aggregate declarations and oversized decoded chunks passed;
  Core stores every chunk, concatenates all content, and materializes the full
  artifact before range slicing.
- **Violated requirement:** Specification §§20.4-20.5 require hard ceilings
  before allocation, bounded authenticated retrieval, and retention policy.
- **Remediation:** Enforce aggregate/cumulative quotas, stream verification and
  persistence, expire abandoned ingests, and serve range slices without loading
  the entire blob.
- **Regression test:** Exercise declaration, per-chunk, cumulative, concurrent,
  abandoned-ingest, and bounded-range resource limits.

### SP-03 — Semantic payload and rate controls are incomplete

- **Severity:** Medium
- **Affected:** `packages/protocol/src/index.ts:467-492,549-555` and
  `apps/core/src/server.ts:544-582,696-751`.
- **Reproduction:** Send a 262,145-byte command-output batch, then burst 500 valid
  `sessions.list` messages over one browser connection.
- **Evidence:** The oversized output passed Connector schema validation (Core
  later silently drops it). All 500 requests received replies with no throttle
  or close. There is no heartbeat, idle timeout, or violation budget.
- **Violated requirement:** Specification §16.5 requires message size, command
  rate, heartbeat/idle, and disconnect controls; §20.4 sets a 256 KiB output
  batch ceiling at the decoded semantic boundary.
- **Remediation:** Put semantic byte maxima in schemas/boundary validators, return
  stable rejection codes instead of silent drops, add per-identity token buckets,
  heartbeat/idle policy, and close repeated protocol violators.
- **Regression test:** Test exact boundaries, multi-byte UTF-8, burst and sustained
  rates, violation budgets, heartbeat expiry, and recovery after backoff.

### SP-04 — The included project-root security boundary is absent

- **Severity:** High
- **Affected:** `apps/connector/src/main.ts:13-27` and all provider operations
  rooted by `CodexProvider.#options.cwd` in `adapter.ts`.
- **Reproduction:** Launch with an outside/system/junction-escaped project path.
- **Evidence:** Raw environment configuration becomes provider cwd; no canonical
  allowlist or Windows-specific containment implementation/tests exist.
- **Violated requirement:** Prototype scope includes one allowlisted root; M6.2
  explicitly names canonical paths and Windows symlink/junction escapes, and
  specification §16.6 defines fail-closed resolution steps.
- **Remediation:** Add canonical project registration and deny-by-default path
  policy before launching or resuming provider work.
- **Regression test:** Cover outside-root, system roots, UNC/device paths,
  symlink/junction escapes, aliases, non-existent targets, and allowed root.

### SP-05 — Provider environment is not allowlisted

- **Severity:** High
- **Affected:** `apps/connector/src/codex/rpc-process.ts:149-159`.
- **Reproduction:** Add a canary credential to the parent environment and inspect
  the child provider environment.
- **Evidence:** The complete `process.env` object is spread into provider spawn.
- **Violated requirement:** Specification §16.9 states that the provider
  environment is created from an allowlist and secrets stay in provider home or
  OS credential storage.
- **Remediation:** Define the minimum required environment per platform and Codex
  authentication mode; explicitly omit application/database/cloud secrets.
- **Regression test:** Canary credentials are absent while compatibility probe,
  real provider startup, authentication, and Windows PATH resolution still pass.

### SP-06 — Provider error details cross boundaries without redaction

- **Severity:** Medium
- **Affected:** `apps/connector/src/client.ts:241-301`
  (`interrupt`, `approval.resolve` failures),
  `apps/core/src/server.ts:610-624`, and console logging at
  `apps/core/src/server.ts:717,746-750`.
- **Reproduction:** Make provider interrupt throw
  `Authorization: Bearer AICL_TEST_SECRET` and observe the subscribed browser.
- **Evidence:** The exact canary reached `protocol.error.message`. Targeted tests
  also printed unredacted absolute paths/stacks during a teardown race. No
  centralized redactor or safe error-detail contract exists.
- **Violated requirement:** The M6.2 prompt forbids unsafe error detail leakage;
  specification §16.9 requires redaction of tokens, cookies, auth headers,
  private keys, and secret-like values in logs.
- **Remediation:** Map provider failures to stable public codes/messages, keep
  bounded sanitized diagnostics locally, redact known secret patterns before any
  log/protocol sink, and avoid exposing raw stacks or absolute paths by default.
- **Regression test:** Canary bearer, cookie, API key, private key, URL credential,
  stack, and path values must not appear in WebSocket frames, logs, or snapshots.

## Verified Controls and Falsified Hypotheses

- Core and Connector health servers bind to `127.0.0.1` by default.
- WebSocket transport enforces a 1 MiB `maxPayload`; `decodeJson` independently
  checks decoded UTF-8 length, and normalized envelopes use strict Zod objects.
- Browser prompts are capped below the 256 KiB requirement, Connector output
  batching uses UTF-8 accounting, and inline diffs cross to artifact transport.
- Artifact routes use opaque identifiers backed by SQLite blobs rather than local
  paths. Bearer checks, hash/length validation, single-range syntax, unauthorized
  retrieval, and traversal denial pass existing tests.
- No unrestricted `shell.exec` endpoint exists. Windows process invocation uses
  a centralized quoting helper and process-tree termination is tested. Because
  current command/arguments are static or operator configured, no command
  injection exploit was established; `shell: true` remains a review point if
  command selection ever becomes remotely controlled.
- React renders command output and diffs as text; no `innerHTML`,
  `dangerouslySetInnerHTML`, `eval`, or `new Function` sink was found.
- Approval compare-and-set rejects stale revision, expired authority, provider
  loss, and Runtime-generation replay. Caller authentication is the missing
  outer boundary, not the row-level CAS itself.
- Core never exposes raw provider events or raw provider request IDs to Web.
- SQLite data files are ignored by Git, and no tracked real credential file was
  found; `.env.example` contains configuration placeholders only.
