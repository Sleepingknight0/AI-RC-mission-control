## Outcome

Provider-native Codex Sessions no longer appear empty when their thread has
history. AICL opens the exact provider/account/thread as a read-only mirror,
reconstructs bounded history, follows observed provider changes, and renders
them separately from AICL-managed durable Turns. Observation performs no
provider Turn start/resume and grants no remote-control authority.

M10.1 was first recovered onto the final SpaceX V2 lineage in checkpoint
`5e62cfc6f6755a360874f09611ec988a3f4f1cc6`. The stale historical branch,
master, and the original seven-file dirty worktree remain unchanged.

Generated-schema compatibility remains SHA-256
`b767c1161c2c56341f3d0e313b4f93810b4b53bdaabeff95c06e1242cfc4df03`.
The installed stable request schema verifies:

- `thread/list`
- `thread/loaded/list`
- `thread/read` with `{ threadId, includeTurns?: boolean }`
- `thread/unsubscribe`

It also defines process-local `thread/status/changed`, `turn/started`,
`turn/completed`, `item/started`, `item/completed`,
`item/agentMessage/delta`, `item/commandExecution/outputDelta`, and
`item/fileChange/outputDelta` notifications. There is no stable
`thread/subscribe` client request.

Measured read-only behavior against the exact current thread returned existing
Turns/items and more than 70 normalized historical items. A separately spawned
app-server reported that externally owned thread as `notLoaded` and emitted no
historical notification replay. Cross-process following therefore performs a
bounded `thread/read` every 1.5 seconds and marks a short live interval only
when the normalized provider projection actually changes. It does not invent a
command, infer idle, replay a prompt, or consume a provider Turn.

## Normalized projection and trust boundary

`provider.session.projection.snapshot` carries exact `providerId`, `accountId`,
`providerSessionId`, `observedAt`, freshness, Runtime ID/generation, optional
provider revision/cursor, availability, state, and at most 250 normalized items:

- `operator_message`
- `assistant_message`
- `assistant_progress`
- `activity`
- `file_change`
- `turn_state`

Every item retains a stable provider item identity. Refresh replaces the
snapshot and deduplicates by provider identity, so externally originated items
never masquerade as AICL durable Turn/Event IDs. Core sends a response only to
the requesting browser after exact provider/account/thread, enabled-provider,
Connector boot, Runtime-generation, and freshness checks.

No raw provider event is a Web protocol member. Text is control/ANSI stripped,
secret redacted, and limited to 16 KiB per preview; a projection is limited to
250 items and 600 KiB before the existing WebSocket ceiling. Full sensitive
paths are reduced to safe labels or `[PATH]`. Environment values, credentials,
auth files, runtime tickets, and secret headers are excluded.

The final production review also fails closed for shell environment references,
environment APIs, sensitive files/options, headers, and tickets in command
titles. Codex 0.146.0 exposes only one unstructured `aggregatedOutput` stream;
that arbitrary output remains Connector-side instead of being treated as a
provably safe browser preview. The provider-neutral protocol retains bounded
structured stdout/stderr fields for future adapters that expose a genuinely
safe structured channel. Whole-snapshot validation, including metadata and
separators, enforces the exact 600 KiB ceiling.

## History, live following, and reconnect

Opening a native Session requests its exact account-scoped thread and shows
existing operator/assistant text, assistant progress, file changes, supported
tool/command activity, and Turn terminal state in provider order. A readable
empty provider history has a distinct truthful empty state; failed/unsupported
reads show `Provider history unavailable` / `Remote activity unavailable`.

New provider content advances the visible timeline without refresh. The header
shows the full `LIVE · <state>` label only while supported provider state or newly observed
content justifies it; otherwise it is `View only` rather than a fabricated
idle state. When scrolled up, the bounded update counter exposes Return to live.
Refresh/session reconnect performs a new read of the same exact triple,
rebuilds history, and never auto-selects a different account.

The sampled live thread exposed commentary and file-change items but no
`commandExecution` item during the observation window. Installed schema support
and deterministic normalization/UI tests cover bounded running-command cards,
completion, failure, and optional structured previews. Existing historical
final assistant messages and completed/interrupted Turn state rendered in
compiled Web; the live-to-final replacement is deterministic regression
evidence because this report cannot observe its own final response before it is
sent.
